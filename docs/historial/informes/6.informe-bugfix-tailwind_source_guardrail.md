# 6. Informe — bugfix: un informe markdown rompía el CSS de la app

- **Feature / tarea:** n/a — bugfix + hardening (no es una feature de `feature_list.json`)
- **Fecha de cierre:** 2026-07-25
- **Cadena de agentes:** usuario reporta el crash → leader diagnostica y aplica el fix inmediato →
  implementer construye el guardrail → leader verifica
- **Reports crudos:** `progress/reports/impl_tailwind_source_guardrail.md`

## El QUÉ — qué pasó y qué se arregló

`pnpm dev` dejó de compilar y la app devolvía **500** en todas las páginas:

```
./src/app/globals.css:785:30  Parsing CSS source code failed
  .duration-\[var\(--dur-\*\)\] { --tw-duration: var(--dur-*); … }
Unexpected token Delim('*')
```

El error apuntaba a `globals.css`, pero **el archivo culpable era un `.md`**. La línea 69 de
`progress/reports/impl_ui_shell_nav.md` — un informe escrito por el implementer al cerrar la feature #13 —
documentaba una convención así:

> el hover/transiciones del nav son CSS por token (`transition-[...] duration-[var(--dur-*)]`)

El `*` era una abreviatura humana para "cualquiera de los tokens `--dur-`". **Tailwind v4 no distingue entre
código y documentación**: escanea todos los archivos del repo buscando texto que parezca una clase de
utilidad. Encontró `duration-[var(--dur-*)]`, lo tomó por una clase real y generó
`transition-duration: var(--dur-*)` — CSS sintácticamente inválido, porque `*` no es un carácter legal
dentro de un nombre de variable. Todo el `globals.css` dejaba de parsearse, y con él toda la app.

Se arregló en dos capas: (1) reescribir esa línea del informe (desbloqueo inmediato), y (2) **prohibirle a
Tailwind que escanee la documentación**, para que ningún informe futuro pueda repetirlo.

## El CÓMO — cómo se arregló

**Fix inmediato (leader).** Reescribir la línea del `.md` sin sintaxis de clase con comodín, dejando una
nota explicando el porqué para que nadie la "corrija" de vuelta. Verificado compilando el CSS aparte —sin
tocar el `pnpm dev` del usuario, que tenía tomada la carpeta `.next`— con `postcss` + el plugin de Tailwind:
**0 líneas inválidas**.

**Guardrail (implementer).** Dos directivas en `src/app/globals.css`, complementarias:

```css
@import "tailwindcss" source("../");

@source not "../../progress";
@source not "../../docs";
@source not "../../template";
```

- `source("../")` acota la **detección automática** de archivos a `src/` (la ruta es relativa al CSS, que
  vive en `src/app/`). Nada fuera de `src/` se escanea, ni siquiera carpetas que se creen en el futuro.
- `@source not "…"` deja **explícitas** las tres carpetas prohibidas: defensa en profundidad y, sobre todo,
  documentación del porqué justo donde alguien la leería.

La sintaxis se verificó **contra el paquete instalado**, no de memoria (`context7` no está disponible):
`node_modules/tailwindcss` es la **4.3.3**, y en el bundle real que se ejecuta se leyó el parser del at-rule,
que confirma el prefijo literal `not ` (con espacio), que la ruta **debe ir entre comillas**, que no puede
anidarse, y que el patrón se registra tomando como base **el directorio del CSS** — de ahí las rutas
relativas a `src/app/`.

**Test de regresión** en `src/app/globals-css.test.ts` (6 tests): compila el CSS de verdad y comprueba que
la salida no contiene la firma del bug (`var(--…*)`), que **siguen** apareciendo utilidades reales de
`src/**` (para que un acotado demasiado agresivo no pase inadvertido), y que las carpetas de documentación
no se escanean — esto último sembrando una carnada temporal en `progress/`, `docs/` y `template/`,
recompilando, y borrándolas después.

## El PORQUÉ — por qué así

**Por qué no bastaba con arreglar el `.md`.** El modo de fallo es especialmente malo: es **silencioso hasta
que rompe la app entera**, la causa está en un archivo que nadie considera código, y el mensaje de error
apunta a un archivo inocente. El repo tiene `docs/` (PRD, RFC, SDD, llenos de nombres de clases citados),
`progress/` (informes de agentes que describen implementaciones) y `template/` (un prototipo HTML con clases
que **no** son las de la app). Que Tailwind escanee todo eso es riesgo puro sin ningún beneficio: ahí no hay
ni una clase que la app necesite.

**Por qué se dejaron los dos mecanismos** en vez de uno: el coste es un bloque de 4 líneas en un único
archivo, y el test asegura el **resultado** (esas carpetas no se escanean) y no un mecanismo concreto, así
que sigue siendo válido si mañana se simplifica.

**Lo que la prueba destapó de paso:** con las exclusiones puestas, el CSS generado **adelgaza 2,7 kB**
(30.976 → 28.273 bytes). O sea que `docs/`, `template/` y `progress/` **ya estaban** inyectando utilidades
basura en el CSS de producción; el `*` inválido fue solo la primera que reventó en vez de colarse en
silencio.

## Verificación

- **Prueba de que el guardrail funciona de verdad** (lo más importante, porque una directiva mal escrita
  fallaría en silencio): se sembraron carnadas en las tres carpetas y se compiló en cuatro escenarios.
  Sin exclusiones, las tres carnadas aparecen en el CSS **y el veneno original reproduce el bug exacto**
  (`invalid var(--…*): ["var(--dur-*","var(--dur-*"]`). Con el guardrail puesto y **el veneno todavía en
  `progress/`**: cero carnadas, cero inválidos, y las clases reales de `src/**` intactas.
- **Control negativo del test**: con las directivas comentadas, 3 de los 6 tests **fallan** con un mensaje
  explícito. Restauradas, 6 pasan. El test detecta lo que dice detectar.
- `bash ./init.sh` → **VERDE**, **362 passed | 6 skipped** (antes 356 → +6, los del archivo nuevo; ningún
  test previo tocado). Verificado por el leader además del implementer.
- `pnpm build` → OK, y se inspeccionó el **CSS realmente emitido por el build**: sin `var()` inválidos y con
  las utilidades reales presentes.
- `git status` sin archivos temporales huérfanos.

## Deuda o notas abiertas

1. **El test importa `postcss` sin que esté declarado en `package.json`.** Es dependencia dura de Next y de
   Vite, está hoisteada y pinneada por el `overrides` de `pnpm-workspace.yaml`, así que hoy resuelve de
   forma estable — pero es una dependencia implícita. Si algún día el test falla con "Cannot find package
   'postcss'", la solución es añadirlo como `devDependency` explícita.
2. **Regla de escritura para todos los agentes:** no citar clases de Tailwind con comodines ni inventadas en
   los informes. Con el guardrail ya no rompe nada, pero conviene igual por higiene. Anotado en
   `progress/current.md`.
3. **Vale la pena mirar si otras herramientas escanean `progress/`** con la misma ingenuidad (por ejemplo un
   futuro linter de clases). No hay indicios hoy; queda como sospecha razonable, no como tarea.
